# Plan: Build the "ay-print" printing-business site following the `ay_print` project flow

## Context

The user wants a **new printing-business website** (printed cards, flyers, bags, banners, stickers, etc.)
that reuses the exact architecture/flow of the existing **`ay_print`** real-estate brochure site
(located at `C:\Users\JOEX7\Desktop\Programfile\ay_print`).

The proven flow (`ay_print`) is a **fully static, multi-page website** (HTML + Tailwind CSS + vanilla JS, no backend):
- `package.json` with `build:css` / `watch:css` (Tailwind v3) and `@fortawesome/fontawesome-free`.
- `css/input.css` → `css/output.css` (+ `custom.css`, `fontawesome.min.css`).
- `tailwind.config.js` with brand colors + `.btn-primary/.btn-secondary/.card` component classes.
- Multiple HTML pages sharing a navbar/footer, a strict `Content-Security-Policy`, and `FORMSPREE_ID` placeholders.
- `js/*.js` modules that `fetch('data/*.json')` and render cards/detail, with embedded JSON fallback for `file://`.
- A shared security/UX layer in `js/main.js` (XSS escaping, email/phone validation, loading overlay, mobile nav, animated counters, newsletter Formspree submit).
- `setup.bat`, `SETUP.md`, `DEPLOYMENT.md` for local dev + static hosting.
- `images/`, `data/`, favicons, `site.webmanifest`, `logo`.

**Decisions confirmed with user:**
1. Target folder: reuse the existing **`C:\Users\JOEX7\Desktop\Programfile\Ay-print`** (currently only empty `.qodo/agents` + `.qodo/workflows`).

## Brand theme (light blue + gold)

In `tailwind.config.js` `theme.extend.colors` and `css/input.css` `:root` vars, set (recommended, tune as desired):
- `primary` / `navy` / `dark` = light blue, e.g. `#2E90E6` (or `#3B9EFF`)
- `secondary` / `maroon` = **gold**, e.g. `#C9A227` (or `#D4AF37`)
- `accent` = `#F4E4BC` (soft gold) or `#FFFFFF`
- `maroonDark` = deeper gold `#A8811B`
- `navyLight` = lighter blue `#5AA9E6`
- Keep `gradient-royal` → `linear-gradient(135deg, #2E90E6 0%, #C9A227 100%)`
- Recolor `custom.css` accent borders/hotspots to gold/blue.

## Risks / notes
- **Missing assets**: real product photos, logo, favicons are placeholders — site is functional but visually generic until user supplies art. Document this in `SETUP.md` + `images/README`.
- **`file://` limitation**: JSON fetch fails on `file://`; embedded fallback prevents blank pages, but the live site must be served over HTTP (covered by DEPLOYMENT.md).
- **JSON/JS drift**: `data/products.json` and the embedded fallback in `js/products.js` must stay in sync when editing (same known limitation as `ay_print`).
- Keep the existing empty `.qodo/agents` and `.qodo/workflows` folders untouched.
